# Database Schema

This document describes the API database schema defined in `apps/api/migrations`.

The database is the control-plane metadata store. It stores users, tenants, projects, connector configuration, pipeline definitions, pipeline runs, datasets, and data quality results. It does not store detailed task logs. Runtime logs should live in the observability stack, such as Airflow task logs, Kubernetes pod logs, Prometheus, Grafana, or Loki.

## Migration Files

Current migration:

```text
apps/api/migrations/
  000001_init.up.sql
  000001_init.down.sql
```

Run migrations from `apps/api`:

```bash
migrate -path migrations -database "$DATABASE_URL" up
```

Rollback one migration:

```bash
migrate -path migrations -database "$DATABASE_URL" down 1
```

Check migration version:

```bash
migrate -path migrations -database "$DATABASE_URL" version
```

## Design Rules

- Primary keys are UUIDs.
- UUID values are generated by the backend, not by PostgreSQL defaults.
- Status, type, role, and execution-mode fields are stored as `VARCHAR(50)`.
- Allowed values for those fields should be defined and shared across the backend, frontend, and `pipeline-runtime`.
- Flexible configuration is stored as `JSONB`.
- Secrets are not stored directly in connector config. Connectors store `secret_ref`.
- Pipeline versions are immutable snapshots of the pipeline graph.
- Pipeline runs always reference a specific pipeline version.

```text

  -> org_members -> users
  -> departments -> department_members -> users
  -> projects

  -> environments
  -> connectors
  -> datasets
  -> pipelines

  -> pipeline_versions
  -> triggers

  -> pipeline_step_runs

```

## Tables

### users

Stores platform users.

Key columns:

| Column | Purpose |
|---|---|
| `id` | User UUID generated by the backend |
| `email` | Unique login/email identity |
| `full_name` | Display name |
| `password_hash` | Password hash if using local auth |
| `created_at`, `updated_at` | Timestamps |

### orgs

Stores top-level tenants.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Org UUID |
| `name` | Human-readable org name |
| `slug` | Unique org slug |
| `created_at`, `updated_at` | Timestamps |

### org_members

Many-to-many join table between orgs and users.

Key columns:

| Column | Purpose |
|---|---|
| `org_id` | References `orgs.id` |
| `user_id` | References `users.id` |
| `role` | Org role, stored as `VARCHAR(50)` |
| `created_at` | Join timestamp |

Primary key:

```text
(org_id, user_id)
```

Delete behavior:

```text
delete org -> delete org_members
delete user -> delete org_members
```

### departments

Stores departments inside an org.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Department UUID |
| `org_id` | Parent org |
| `name` | Department name |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (org_id, name)
```

### department_members

Many-to-many join table between departments and users.

Key columns:

| Column | Purpose |
|---|---|
| `department_id` | References `departments.id` |
| `user_id` | References `users.id` |
| `role` | Department role, stored as `VARCHAR(50)` |
| `created_at` | Join timestamp |

Primary key:

```text
(department_id, user_id)
```

### projects

Stores workspaces under an org. Most platform resources belong to a project.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Project UUID |
| `org_id` | Parent org |
| `name` | Project name |
| `slug` | Project slug unique inside org |
| `description` | Optional project description |
| `created_by` | User that created the project |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (org_id, slug)
```

Delete behavior:

```text
delete org -> delete projects
delete creator user -> set created_by null
```

### environments

Stores project environments such as dev, staging, and prod.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Environment UUID |
| `project_id` | Parent project |
| `name` | Environment name |
| `type` | Environment type, stored as `VARCHAR(50)` |
| `config_json` | Environment-specific config such as compute settings |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (project_id, name)
```

### connectors

Stores source and sink connector configuration. Examples: Postgres, SFTP, Kafka, REST API, object storage, warehouse.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Connector UUID |
| `project_id` | Parent project |
| `name` | Connector name unique inside project |
| `type` | Connector type, stored as `VARCHAR(50)` |
| `config_json` | Non-secret connector settings |
| `secret_ref` | Pointer to secret storage |
| `created_by` | User that created the connector |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (project_id, name)
```

Important rule:

```text
Do not store passwords, API keys, tokens, or private keys in config_json.
Use secret_ref for sensitive values.
```

### datasets

Stores logical data assets known to the platform.

Examples:

```text
postgres.public.orders
kafka.click_events
warehouse.analytics.daily_revenue
s3://bucket/raw/customers/
```

Key columns:

| Column | Purpose |
|---|---|
| `id` | Dataset UUID |
| `project_id` | Parent project |
| `connector_id` | Optional connector where the dataset lives |
| `name` | Display name |
| `type` | Dataset type, stored as `VARCHAR(50)` |
| `location` | Physical or logical location |
| `schema_json` | Dataset schema |
| `metadata_json` | Extra metadata |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (project_id, location)
```

Current tradeoff:

```text
Environment-specific dataset locations are not split into a separate table yet.
If this becomes painful later, introduce dataset_locations.
```

### pipelines

Stores the logical pipeline entity.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Pipeline UUID |
| `project_id` | Parent project |
| `name` | Pipeline name |
| `slug` | Pipeline slug unique inside project |
| `description` | Optional pipeline description |
| `status` | Pipeline lifecycle status, stored as `VARCHAR(50)` |
| `execution_mode` | Batch, streaming, or hybrid, stored as `VARCHAR(50)` |
| `current_version_id` | Points to the currently active pipeline version |
| `created_by` | User that created the pipeline |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (project_id, slug)
```

Delete behavior:

```text
delete project -> delete pipelines
delete creator user -> set created_by null
delete current pipeline version -> set current_version_id null
```

### pipeline_versions

Stores immutable snapshots of a pipeline graph.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Pipeline version UUID |
| `pipeline_id` | Parent pipeline |
| `version_number` | Version number unique per pipeline |
| `definition_json` | Full pipeline graph/config snapshot |
| `created_by` | User that created the version |
| `created_at` | Version creation time |

Constraint:

```text
UNIQUE (pipeline_id, version_number)
```

Delete behavior:

```text
delete pipeline -> delete pipeline_versions
delete creator user -> set created_by null
```

Important rule:

```text
Runs reference pipeline_versions, not the mutable pipelines row.
This allows old runs to be explained even after the pipeline changes.
```

### triggers

Stores ways to start a pipeline.

Examples:

```text
manual
schedule
webhook
event
```

Key columns:

| Column | Purpose |
|---|---|
| `id` | Trigger UUID |
| `pipeline_id` | Parent pipeline |
| `name` | Trigger name unique inside pipeline |
| `type` | Trigger type, stored as `VARCHAR(50)` |
| `config_json` | Trigger config such as cron, webhook path, or event pattern |
| `enabled` | Whether trigger is active |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (pipeline_id, name)
```

### pipeline_runs

Stores one execution of a pipeline version.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Pipeline run UUID |
| `pipeline_id` | Logical pipeline |
| `pipeline_version_id` | Exact version that ran |
| `environment_id` | Environment where the run happened |
| `trigger_id` | Trigger that started the run |
| `status` | Run status, stored as `VARCHAR(50)` |
| `run_type` | Batch, streaming, or hybrid, stored as `VARCHAR(50)` |
| `airflow_dag_id` | External Airflow DAG id |
| `airflow_dag_run_id` | External Airflow DAG run id |
| `started_at`, `finished_at` | Execution timestamps |
| `error_message` | Summary error message |
| `metrics_json` | Run-level metrics |
| `created_at` | Row creation timestamp |

Delete behavior:

```text
delete pipeline -> delete pipeline_runs
delete pipeline_version referenced by a run -> restricted
delete environment -> set environment_id null
delete trigger -> set trigger_id null
```

Why `pipeline_version_id` uses `ON DELETE RESTRICT`:

```text
A historical run must keep pointing to the exact version that produced it.
```

### pipeline_step_runs

Stores execution state for each node/step in a pipeline run.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Step run UUID |
| `pipeline_run_id` | Parent pipeline run |
| `step_key` | Stable step key from the pipeline graph |
| `step_name` | Display name |
| `status` | Step status, stored as `VARCHAR(50)` |
| `airflow_task_id` | External Airflow task id |
| `started_at`, `finished_at` | Step execution timestamps |
| `error_message` | Summary step error |
| `input_metadata_json` | Input metadata, schema, row counts, offsets, etc. |
| `output_metadata_json` | Output metadata, schema, row counts, output dataset refs, etc. |
| `metrics_json` | Step-level metrics |
| `created_at` | Row creation timestamp |

Constraint:

```text
UNIQUE (pipeline_run_id, step_key)
```

Detailed logs are intentionally not stored here. Use Airflow/Kubernetes/Grafana for full logs.

### data_quality_rules

Stores data quality rules attached to datasets.

Examples:

```text
not_null
unique
row_count
freshness
accepted_values
custom_sql
```

Key columns:

| Column | Purpose |
|---|---|
| `id` | Rule UUID |
| `dataset_id` | Dataset being checked |
| `name` | Rule name unique inside dataset |
| `type` | Rule type, stored as `VARCHAR(50)` |
| `config_json` | Rule configuration |
| `enabled` | Whether rule is active |
| `created_at`, `updated_at` | Timestamps |

Constraint:

```text
UNIQUE (dataset_id, name)
```

### data_quality_results

Stores results from data quality checks.

Key columns:

| Column | Purpose |
|---|---|
| `id` | Result UUID |
| `rule_id` | Data quality rule |
| `pipeline_run_id` | Optional pipeline run |
| `pipeline_step_run_id` | Optional pipeline step run |
| `status` | Result status, stored as `VARCHAR(50)` |
| `observed_value` | Observed check value |
| `message` | Human-readable result message |
| `metadata_json` | Extra check metadata |
| `checked_at` | Check timestamp |

Delete behavior:

```text
delete rule -> delete results
delete pipeline run -> set pipeline_run_id null
delete pipeline step run -> set pipeline_step_run_id null
```

## Important JSON Columns

### `pipeline_versions.definition_json`

Stores the canonical pipeline graph snapshot.

Expected shape:

```json
{
  "schema_version": "1",
  "nodes": [],
  "edges": []
}
```

Each node should include enough information for the runtime compiler to create an executable plan.

### `connectors.config_json`

Stores non-secret connector settings.

Example:

```json
{
  "host": "localhost",
  "port": 5432,
  "database": "analytics",
  "ssl_mode": "disable"
}
```

Sensitive values should be referenced through `secret_ref`.

### `datasets.schema_json`

Stores discovered or declared schema.

Example:

```json
{
  "columns": [
    { "name": "id", "type": "uuid", "nullable": false },
    { "name": "created_at", "type": "timestamp", "nullable": false }
  ]
}
```

### `pipeline_runs.metrics_json`

Stores run-level execution metrics.

Example:

```json
{
  "duration_ms": 12500,
  "rows_read": 100000,
  "rows_written": 99990
}
```

### `pipeline_step_runs.input_metadata_json` and `output_metadata_json`

Stores step-level input/output metadata.

Examples:

```json
{
  "dataset_id": "uuid",
  "rows_read": 100000,
  "schema_hash": "abc123"
}
```

```json
{
  "dataset_id": "uuid",
  "rows_written": 99990,
  "output_location": "warehouse.analytics.orders_cleaned"
}
```

## Deferred Tables

These are intentionally not part of the current schema:

```text
connector_tests
run_logs
audit_logs
lineage_nodes
lineage_edges
dataset_locations
```

Reasons:

- `connector_tests`: can be represented initially as a live API call or later as last-test fields on `connectors`.
- `run_logs`: detailed logs should live in Airflow/Kubernetes/Grafana/Loki.
- `audit_logs`: useful later for governance and compliance, but not required for the initial data flow.
- `lineage_nodes` and `lineage_edges`: useful later for global lineage views.
- `dataset_locations`: useful later if the same logical dataset has different physical locations per environment.
